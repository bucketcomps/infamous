Why the movie crawls: our clock and the missing screen refresh. Both being rebuilt

The movie plays slowly for two different reasons. One is expected: we run the game one instruction at a time in Python (about 71,000 per second; a real PS3 does billions), so everything takes ages on the wall clock. The other is a real bug in our model: inside the game's own world the movie is ~27× too slow, because the game redraws the screen 55 times per movie frame instead of 2.

  • The movie plays slowly for two different reasons. One is expected: we run the game one instruction at a time in Python (about 71,000 per second; a real PS3 does billions), so everything takes ages on the wall clock. The other is a real bug in our model: inside the game's own world the movie is ~27× too slow, because the game redraws the screen 55 times per movie frame instead of 2.
  • Cause 1, the clock: our model counts 1 microsecond of game time for every instruction. A real PS3 does over a thousand instructions in that microsecond, so the game's sense of time races ~1,000× ahead of the work. To the game, the video decoder looks hopelessly slow, the sound buffer keeps running dry, and timeouts fire far too early.
  • Cause 2, no screen refresh: a real PS3 shows a new frame only on the TV's refresh, 59.94 times a second. Our model has no refresh at all. A frame is shown the instant the game asks.
  • Being built now: a hardware-scaled clock plus a 59.94 Hz refresh on that same clock, behind a switch that's off by default, so nothing changes until it's proven. The pass mark: the movie plays at ~30 frames per second of game time with ~2 refreshes per frame.
  • Speed work, separate: the main processor spends most of its effort asking "is the decode done yet?" in a tight loop. A shortcut that skips that loop exactly (the game sees identical numbers) is built, and two boots, one with it on and one off, are running side by side to prove the game can't tell the difference and to measure the gain. Native helper-chip code measured ~1.35× faster.
  • Save points: saves now split giant lists across several checked files (format v4), after a save at ~750M refused because one log outgrew a single file.

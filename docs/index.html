Carry-flag bug fixed in every CPU model; probe data now public

XER carry fixed everywhere. An audit found that our CPU models mishandled the carry flag on the add/subtract-with-carry and shift instructions. That covers the boot interpreter, the C interpreter, the native core and the C generator. In the boot interpreter, addze ignored the carry, so the compiler's usual signed-divide pattern (srawi+addze, 203 places in the game) could be off by one on negative numbers. dcbz (clear a cache line) did nothing in three of the models. All of them now match the Power ISA exactly. An independent reviewer rebuilt the reference from the spec and found 0 mismatches.

Movie stall narrowed: the game's clock stops, not a timeout loop; RPCS3 fix batch 2 passes review

Movie stall, first measurement (not yet independently reviewed): replaying boot 5 from its save reproduces the wall exactly. The main thread gets zero wait timeouts and does receive the movie player's signal at 251.018 ms. Then guest time freezes at 277.766 ms while the SPU is parked, even though the movie player's next wake-up is only 2.7 µs away. So the leading suspect is now our idle-time advance refusing to move the clock, not starved SPUs or a lost signal. The fix is in progress.

  • Measured on a real save point: the new direct path runs 1.15–1.2× faster on the game, not the 2.19× a synthetic test showed. We ran old and new side by side three times on the same 5-million-instruction stretch. The game's state came out byte-for-byte identical in all six runs, across 15 separate parts of it.
